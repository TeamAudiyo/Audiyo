# Community

Audiyo is small and we want to keep it friendly.

## Be kind

Assume good intent. Criticize code, not people. If someone is new, point them at the docs. If a discussion gets heated, step away and come back later.

## What belongs here

* Bug reports with steps to reproduce.
* Benchmark numbers from real hardware, with the header attached so others can compare.
* Small focused pull requests: better errors, more checks, docs fixes, test coverage.
* Questions about memory modes, datasets, and LoRA setups.

## What does not

* Requests to support other models. Version 0.1 is Stable Audio Open only, on purpose. Open an issue to discuss scope before writing code for a new backend.
* Benchmark claims without hardware and version info.
* Weights, adapters trained on audio you cannot share, clips you do not own, tokens, or personal data. Do not post any of that in issues or pull requests.
* Spam, harassment, hate speech, or sexual content. These get removed and repeat offenders get blocked.

## How decisions get made

Maintainers review issues and pull requests as time allows. Small fixes go in fast. Bigger changes need agreement on scope first. If a proposal is declined, it is about fit and upkeep cost, not about you.
